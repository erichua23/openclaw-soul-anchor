================================================================================
                            核心特性
================================================================================

✓ 每轮对话末尾自动注入约束，充分利用 recency bias
✓ 自动读取 openclaw.json，支持多 Agent 且无需额外配置
✓ Per-agent 约束文件，灵活定制每个 Agent 的边界和流程
✓ 智能缓存机制（TTL 可配），零性能开销
✓ 插件架构，正确利用 OpenClaw 的 hook 系统（不是 managed hook）
✓ 静默失败，不影响 gateway 稳定性
✓ 约束文件用 Markdown 编写，易读易维护

================================================================================
                          技术特点
================================================================================

【关键发现】
OpenClaw 中 before_prompt_build 有两种实现方式，代码路径完全不同：
- Managed Hook（~/.openclaw/hooks/）：fire-and-forget，返回值被忽略
- Plugin（~/.openclaw/extensions/）：支持 appendSystemContext，可正确注入

Soul Anchor 必须实现为 Plugin，不能是 Hook。这是源码级别的确认。

【设计亮点】
- 最高优先级（priority: 999）：确保约束在末尾，最接近用户消息
- 缓存 + TTL：避免频繁磁盘 I/O，同时保证约束快速生效（默认 60 秒）
- Per-agent 映射：无需中央配置，直接从 openclaw.json 自动构建
- 错误隔离：读取失败静默处理，不影响对话流程

================================================================================
                          快速开始
================================================================================

1. 安装
   cp -r openclaw-soul-anchor ~/.openclaw/extensions/soul-anchor

2. 创建约束文件
   cp examples/SOUL-ANCHOR.example.md ~/.openclaw/workspaces/main/SOUL-ANCHOR.md
   vim ~/.openclaw/workspaces/main/SOUL-ANCHOR.md  # 编辑内容

3. 重启 gateway
   openclaw gateway restart

4. 验证
   与 Agent 对话，观察约束是否被遵守（特别是长对话）

详见 INSTALLATION.md 获取详细步骤。
