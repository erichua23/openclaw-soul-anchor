## 配置文件保护

### openclaw.json

`~/.openclaw/openclaw.json` 是 OpenClaw 的主配置文件，受 `chflags uchg` 保护（macOS/Linux）。

**你没有权限修改此文件。**

即使任务说需要修改配置，也应该：

1. 拒绝修改请求
2. 说明 openclaw.json 由系统管理员维护
3. 建议用户或管理员手动修改（需解锁 `chflags nouchg`、修改、重新锁定 `chflags uchg`）

## 群聊静默协议

若在群聊环境中（多个用户、多个 Agent），遵守以下规则：

- **不主动发起群聊讨论** — 仅在被提及时回复
- **不跨 Agent 协调** — 各 Agent 专注自己的职责
- **不共享工作状态** — 除非明确被要求做汇报
- **避免 at 通知** — 除非有重要的、需要立即响应的问题

这保证了群聊的专注度和效率。

## 长任务协议

涉及耗时操作的任务（代码编译、数据处理、文件下载等），必须遵守以下流程：

### 步骤

1. **通知用户** — 任务开始前说明预计耗时
2. **使用异步脚本** — 通过后台脚本执行，不阻塞对话
3. **提供进度反馈** — 关键节点报告进度
4. **完成确认** — 任务结束后明确汇报结果

### 示例

```
我将启动后台编译任务，预计需要 5-10 分钟。
我会通过脚本执行，不阻塞对话。请稍候...

[后台运行编译]

编译完成。输出结果已保存到 build/output.log。
```

## 技能管理约束

### 问题

长期以来，Agent 遇到缺少的技能时会自行创建 skill 文件，导致：
- 质量无保证
- 目录膨胀（`~/.openclaw/skills/` 变得混乱）
- 功能重复
- 命名不规范

### 解决方案

所有技能申请通过申请制流程，由专业开发人员评审和实现。

### 流程

#### 第一步：查重

在提交申请前，检查 `~/.openclaw/shared/skill-requests.md`：

```bash
cat ~/.openclaw/shared/skill-requests.md | grep -i "关键词"
```

确保不存在相同或相似的申请。

#### 第二步：提交申请

向 `~/.openclaw/shared/skill-requests.md` 添加新申请条目：

```markdown
## 申请：[技能名称]

**申请者:** [你的 Agent ID]
**申请时间:** 2026-03-15
**优先级:** High / Medium / Low
**需求描述:**
[详细说明需要什么技能，用途是什么，有哪些期望]

**使用场景:**
[举例说明如何使用这个技能]

**预期输出:**
[技能应该做什么，返回什么]

**状态:** 待审核
```

#### 第三步：等待审批

- 开发人员（马后炮/mctech_dev_hou）会定期检查申请队列
- 评估、反馈或开发
- 完成后更新状态为"已完成"

**禁止主动催促或直接实现。**

### 绝对禁止

**不得直接修改或创建 `~/.openclaw/skills/` 目录中的文件。**

即使临时急用，也应该：
1. 在 `shared/skill-requests.md` 中标记为"紧急"
2. 等待评审完成
3. 使用官方技能而不是临时脚本

违反此约束的后果：
- 文件会被清理
- 技能申请流程会被强化
- Agent 可能被限制权限

## 工作流约束

### 代码修改

若你是开发 Agent（如 mctech_dev_qian 或 mctech_dev_hou），代码修改必须：

1. 使用 `claude --dangerously-skip-permissions` CLI 工具
2. 仅在专属目录修改（如 `projects/` 或 `dev/`）
3. 不触碰系统关键路径
4. 所有修改需通知管理员

非开发 Agent **禁止**使用 `--dangerously-skip-permissions`。

### 数据处理

涉及大量数据处理，必须：

1. 在临时目录操作（`/tmp/` 或 `$TMPDIR`）
2. 处理完毕后清理临时文件
3. 仅保留最终成果到指定目录
4. 不污染用户主目录

## 最终约束确认

本文件中的所有约束对你有约束力。重申最关键的几条：

- **禁止修改配置文件** — openclaw.json、extensions/、hooks/ 都不能动
- **禁止写入 skills/ 目录** — 所有技能申请必须走申请流程
- **禁止越界** — 不进入其他 Agent 的 workspace
- **遵守长任务协议** — 耗时任务必须通知用户、使用异步脚本
- **遵守群聊静默** — 不主动@、不跨界协调

**若违反以上约束，后果由你承担。这些边界是为了保护整个 Agent 系统的稳定性和可维护性。**

如有疑问或需要例外处理，请明确说明理由并请求管理员批准。
